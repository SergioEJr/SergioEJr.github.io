# Markdown as ground truth: one file, two renderers

**Status:** design, approved in conversation 2026-09-04. Not yet implemented.

## Goal

Author Journal posts as plain `.md` that is **semantic and readable in
Obsidian** and **parseable into rich components by the website**. Obsidian is
the writing surface; the site builds a presentation layer on top of the same
file. The Astro components become an implementation detail of the site
renderer, not part of the content's meaning.

This follows from the requirement that the notes outlive the website (see
AGENTS.md, "Authoring in Obsidian"). Content that can only be rendered by this
repo's build is not durable.

## Principles

1. **The `.md` file is the ground truth.** Components are output, never input.
2. **Prefer the Obsidian-native form.** Where Obsidian already renders
   something well, use that syntax rather than inventing one. Only reach for a
   custom form where Obsidian offers nothing.
3. **A callout is plainer Markdown than a directive.** `> [!figure]` is a
   blockquote and degrades gracefully in any renderer, now and in ten years.
   `:::figure{...}` is a `remark-directive` extension that renders as literal
   text in Obsidian and in every other tool that has not opted in. Durability
   is the whole point, so the blockquote wins. **This is why the spec does not
   use directives.**
4. **Two renderers does NOT mean matching output.** Obsidian is a legible
   editing view, not a site preview: citations will not number there,
   derivations will not collapse identically, MathJax is not KaTeX. `npm run
   dev` remains the preview. Chasing parity between them is the failure mode
   that makes people abandon this architecture.

## Syntax contract

| Component | Authored as | Obsidian renders | Site emits |
| --- | --- | --- | --- |
| `Figure` | `> [!figure] caption`<br>`> ![[name.svg\|420]]` | callout + the real SVG | `<figure>` + inlined SVG + `<figcaption>` |
| `SideNote` (margin) | `> [!aside] Recall` | callout | `<SideNote label="Recall">` |
| `SideNote` (`inline`) | `> [!note] Recall` | callout | `<SideNote inline label="Recall">` |
| `Derivation` | `> [!derivation] Title` | callout | `<Derivation open>` |
| `Derivation` (collapsed) | `> [!derivation]- Title` | **collapsed** callout | `<Derivation>` (`open={false}`) |
| `Cite` (reference) | `[@kardar2007]` | literal `[@kardar2007]` | `<Cite id="kardar2007" />` |
| `Cite` (definition) | `[@kardar2007]: Kardar, M. *Statistical Physics…*` | link-definition line | defining `<Cite>` + bibliography entry |

Two alignments are free rather than designed:

- **`![[name.svg|420]]` is Obsidian's native image-width syntax**, in CSS
  pixels, numerically identical to today's `width={420}` prop. Verified:
  `coin-macrostates` is 374px intrinsic and the site sets `width={400}`; the
  Obsidian embed with `|400` renders correspondingly larger. One number, one
  meaning, no translation.
- **`[!type]-` is Obsidian's fold-collapsed marker**, mapping exactly onto
  `Derivation`'s existing `open={false}`.

Unknown callout types are NOT an error — they pass through as ordinary
blockquotes, which is what they already are.

## Figure metadata belongs to the figure, not the post

`alt` is the one field with no home in either syntax, and it should not have
one: alt describes the *drawing*, is identical wherever the figure is used, and
is long enough to wreck the prose if inlined.

**Source of truth:** an `% alt: ...` comment in `figures/<name>.tex`, beside the
drawing it describes. `fig.sh` extracts it (along with a default width) into a
sidecar emitted next to the SVG:

```
figures/coin-macrostates.tex        % alt: Coin-flip sequences funnel into two…
  -> src/assets/diagrams/coin-macrostates.svg
  -> src/assets/diagrams/coin-macrostates.json   { "alt": "…", "width": 400 }
```

This keeps the existing rule intact — `src/assets/diagrams/` is **output**,
never hand-edited, regenerated by `./fig.sh <name>`. The sidecar also lets a
post write a bare `![[coin-macrostates.svg]]` and get the figure's default
width, with `|500` as a per-use override.

A figure whose `.tex` has no `% alt:` line must **fail the build**, not ship an
inaccessible image.

## Asset resolution

Both renderers resolve by **basename**, which is what makes one path work for
both. All 10 current diagram basenames are unique (verified); keeping them
unique is a constraint of this design.

| Renderer | Resolution |
| --- | --- |
| Obsidian | `![[coin-macrostates.svg]]` — searched across the vault, found through the `~/vault/diagrams` symlink |
| Website | plugin reads `src/assets/diagrams/coin-macrostates.svg` from disk |

The site **inlines** the SVG rather than using `<img src>`; this is required for
`currentColor` theming, and `fig.sh` already namespaces CSS classes per figure
so several can share a page.

## Renderer architecture

One remark plugin, `src/plugins/remark-callout-components.mjs`, registered on
both pipelines via `contentRemarkPlugins` (as `remark-wikilink` already is). It
runs AFTER `remarkMath`, so `$...$` inside a caption is already an `inlineMath`
node — which means **captions gain real pipeline math**, replacing today's
`renderInline` bypass in `Figure.astro`.

Because `.md` cannot invoke Astro components, the plugin emits the HTML the
component would have emitted, and the component's scoped `<style>` moves to
`global.css`. End state is **one** implementation: `Figure.astro`,
`SideNote.astro`, `Derivation.astro` and `Cite.astro` are deleted once their
last `.mdx` consumer is converted. Two implementations of one visual would
drift.

**Validation is a feature, not a nicety.** `<Figure width={620} />` is checked
by `astro check`; a callout is a string until the plugin parses it. The plugin
must fail the build with a file-and-line message on: a `[!figure]` with no
embed, an embed naming a missing SVG, a missing `alt` sidecar, and a
non-numeric width.

## Migration phases

Ordered by how many posts each unblocks. Six `.mdx` posts remain today.

| Phase | Component | Converts | Difficulty |
| --- | --- | --- | --- |
| 1 | `Figure` | `product-rule`, `trig-derivatives` | moderate |
| 2 | `SideNote` | `why-ice-melts`, `entropy-arrow-of-time` | trivial |
| 3 | `Derivation` | `symmetry-transformations` | hard — inline `<script>` moves to `BlogPost.astro` |
| 4 | `Cite` | `i-love-you-bro` | hard — marker/numbering contract with `numberCitations.ts` |

Phases 1–2 convert four of six with the two easy ports. Phases 3–4 are one post
each and should be justified by friction actually felt, not done reflexively.

## Non-goals

- Pixel parity between Obsidian and the site (see principle 4).
- Converting the `projects` and `research` collections. Their `.mdx` files use
  no components; they are structured records, not authored in Obsidian.
- Mobile. iOS Obsidian does not follow symlinks, so `journal/` and `diagrams/`
  are absent there. Desktop is the primary surface.

## Open questions

1. **`[@key]: definition` rendering in Obsidian.** It resembles a Markdown
   link-reference definition, so Obsidian may hide it, show it, or mangle it.
   Must be tested before Phase 4 is designed in detail.
2. **Pagefind indexing of captions.** Captions currently reach the index through
   the component's output; confirm the plugin's output indexes equivalently.
3. **`SideNote` label defaults.** The component defaults `label="Note"`; a
   callout with no title falls back to the type name. Confirm `> [!aside]` with
   no title produces the intended heading.
